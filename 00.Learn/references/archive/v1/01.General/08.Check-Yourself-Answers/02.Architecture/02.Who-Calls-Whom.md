# Answers: Who Calls Whom?

[← Back to the post](../../02.Architecture/02.Who-Calls-Whom.md)

**1. The KVM host's firewall blocks every incoming connection except SSH. Can the head office still start VMs on it? And if you block incoming 8250 on the management server instead?**

**Yes, the head office can still give orders.** Nothing on the host needs to accept a connection for that:

- The attendant (the KVM agent) opens the line itself, outwards, to port 8250 on the management server ([Dialling in](../../02.Architecture/02.Who-Calls-Whom.md#dialling-in-with-id-on-both-ends)).
- Instructions such as "start this VM" come back down that same line, which the head office writes to ([Instructions come back on the same call](../../02.Architecture/02.Who-Calls-Whom.md#instructions-come-back-on-the-same-call)).
- SSH, port 22, stays open, and that's all the head office needs for setup and repairs: adding the host, installing certificates, restarting the agent.

That's the pay-off of the attendant dialling out: a host can refuse everything inbound and still be managed.

**But not everything keeps working.** Some traffic does come *into* a KVM host ([the port table](../../02.Architecture/02.Who-Calls-Whom.md#who-talks-to-whom-the-whole-map)):

- the console proxy VM connects to the host's VNC ports, 5900–6100, to show a VM's screen, so consoles break;
- live migration needs libvirt's ports (16509, 16514) and 49152–49216 between hosts, so moving a running VM onto this host breaks.

Starting and stopping VMs works; watching them and moving them doesn't.

**Now block incoming 8250 on the management server.** That's the one door every attendant uses, so every attendant that has to dial in can't:

- **A new host never joins.** `addHost` logs in over SSH, runs the setup script, then waits for the agent to phone in. It waits five minutes ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/hypervisor/kvm/discoverer/LibvirtServerDiscoverer.java#L73)):

    ```java
    // cloudstack: server/src/main/java/com/cloud/hypervisor/kvm/discoverer/LibvirtServerDiscoverer.java, line 73
    private final int _waitTime = 5; /* wait for 5 minutes */
    ```

    It checks twice a minute for an Up host with the new host's ID, then gives up ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/hypervisor/kvm/discoverer/LibvirtServerDiscoverer.java#L356-L370)):

    ```java
    // cloudstack: server/src/main/java/com/cloud/hypervisor/kvm/discoverer/LibvirtServerDiscoverer.java, lines 356–370
    private HostVO waitForHostConnect(long dcId, long podId, long clusterId, String guid) {
        for (int i = 0; i < _waitTime * 2; i++) {
            List<HostVO> hosts = _resourceMgr.listAllUpAndEnabledHosts(Host.Type.Routing, clusterId, podId, dcId);
            for (HostVO host : hosts) {
                if (host.getGuid().toLowerCase().startsWith(guid.toLowerCase())) {
                    return host;
                }
            }
            try {
                Thread.sleep(30000);
            } catch (InterruptedException e) {
                logger.debug("Failed to sleep: " + e.toString());
            }
        }
        logger.debug("Timeout, to wait for the host connecting to mgt svr, assuming it is failed");
    ```

    `_waitTime * 2` rounds of `Thread.sleep(30000)`, 30 seconds each, make five minutes. The last line is the message the code logs when nobody called.

- **A floor whose line drops can't call back.** If the line is cut cleanly, the head office notices at once; if it just goes silent, after 150 seconds plus up to a minute (answer 2 shows the code). Then it investigates.
- **The porter and the window can't call in either.** They dial 8250 too. In the web UI's System VMs list, their *State* can be Running while their *Agent State* isn't Up: the VM runs, but its phone is dead. Without the porter, room styles don't download; without the window, consoles fail.

VMs that are already running carry on, though, yours and your users': they run on the hosts, not on the line.

**2. A host's agent hangs, its connection still open but no more check-ins, while its VMs keep running. What does CloudStack do, how long does it wait, and why doesn't it restart the VMs elsewhere at once?**

**First, nothing happens for a while.** A hung attendant still holds its line open, so the head office only counts the silence. Its patience is `ping.timeout` × `ping.interval` ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/schema/src/main/java/com/cloud/configuration/ManagementServiceConfigurationImpl.java#L42-L45)):

```java
// cloudstack: engine/schema/src/main/java/com/cloud/configuration/ManagementServiceConfigurationImpl.java, lines 42–45
@Override
public long getTimeout() {
    return (long) (PingTimeout.value() * PingInterval.value());
}
```

With the defaults, 2.5 × 60 = 150 seconds. The head office checks for silent attendants on a timer that fires once every ping interval ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L437)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, line 437
_monitorExecutor.scheduleWithFixedDelay(new MonitorTask(), mgmtServiceConf.getPingInterval(), mgmtServiceConf.getPingInterval(), TimeUnit.SECONDS);
```

Each round compares the time of every attendant's last call with "now minus 150 seconds" ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L2050-L2056)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, lines 2050–2056
protected List<Long> findAgentsBehindOnPing() {
    final List<Long> agentsBehind = new ArrayList<>();
    final long cutoffTime = InaccurateClock.getTimeInSeconds() - mgmtServiceConf.getTimeout();
    for (final Map.Entry<Long, Long> entry : _pingMap.entrySet()) {
        if (entry.getValue() < cutoffTime) {
            agentsBehind.add(entry.getKey());
        }
```

`_pingMap` holds the time of each attendant's last call. Any call older than the cut-off puts that attendant on the list. Because the rounds come once a minute, the silence is noticed somewhere between 150 and about 210 seconds after the last call: two and a half to three and a half minutes, by our arithmetic.

**A crash would be noticed sooner.** If the agent's program died outright, the host's kernel would close its connection. The head office reads the hang-up at once ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/utils/src/main/java/com/cloud/utils/nio/Link.java#L228-L229)):

```java
// cloudstack: utils/src/main/java/com/cloud/utils/nio/Link.java, lines 228–229
if (ch.read(_readBuffer) == -1) {
    throw new IOException("Connection closed with -1 on read.");
```

A read that returns `-1` means the other end has closed the line. That ends the connection, and the head office starts the same investigation straight away, without waiting for any timer ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L1814-L1818)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, lines 1814–1818
} else if (type == Type.DISCONNECT) {
    final Link link = task.getLink();
    final AgentAttache attache = (AgentAttache) link.attachment();
    if (attache != null) {
        disconnectWithInvestigation(attache, Event.AgentDisconnected);
```

So the 150-second timer is for a line that goes silent without closing: a hung agent, a frozen host, a cut cable.

**Then it investigates, instead of acting** ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L1157-L1161)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, lines 1157–1161

    /* OK, we are going to the bad status, let's see what happened */
    logger.info("Investigating why host {} has disconnected with event", host, event);

    Status determinedState = investigate(attache);
```

For KVM, the investigation asks the host's neighbours, the Up hosts of the same cluster ([the post shows that code](../../02.Architecture/02.Who-Calls-Whom.md#when-a-floor-goes-quiet)). High availability starts only if the answer is Down, and even then it restarts only the VMs that ask for it ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/ha/HighAvailabilityManagerImpl.java#L778-L783)):

```java
// cloudstack: server/src/main/java/com/cloud/ha/HighAvailabilityManagerImpl.java, lines 778–783

    if (logger.isDebugEnabled()) {
        logger.debug("VM {} is not HA enabled so we're done.", vm);
    }
    return null; // VM doesn't require HA
}
```

`isHaEnabled()` comes from the VM's offering; `ForceHA` is a global setting that turns HA on for every VM. A VM whose disk sits in a floor's cupboard is skipped altogether ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/ha/HighAvailabilityManagerImpl.java#L388-L393)):

```java
// cloudstack: server/src/main/java/com/cloud/ha/HighAvailabilityManagerImpl.java, lines 388–393

    if (_itMgr.isRootVolumeOnLocalStorage(vm.getId())) {
        if (logger.isDebugEnabled()){
            logger.debug("Skipping HA on Instance " + vm + ", because it uses local storage. Its fate is tied to the host.");
        }
        continue;
```

"Its fate is tied to the host": no other floor can reach its disk.

**Why so careful?** CloudStack's 2012 architecture notes put it plainly: "failure to respond to ping does not mean the physical resource is Down", and an investigator that only failed to reach the host should answer "I don't know", not "Down" ([architecture notes](https://cwiki.apache.org/confluence/spaces/CLOUDSTACK/pages/30148035/Alex+s+Architecture+Notes)). Here, the host and its VMs are fine; only the attendant is gone. Our reading, not a stated reason: restarting VMs elsewhere while they still run on this host would be worse than waiting.

**Here, the neighbours report the host alive** (in your one-host lab there's no neighbour to ask, which ends the same way), so the code settles on Disconnected, not Down ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L1192-L1193)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, lines 1192–1193
} else if (determinedState == Status.Disconnected) {
    logger.warn("Agent is disconnected but the host is still up: {} state: {}", host, host.getResourceState());
```

It then alerts the operator ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L1208-L1209)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, lines 1208–1209
_alertMgr.sendAlert(AlertManager.AlertType.ALERT_TYPE_HOST, host.getDataCenterId(), host.getPodId(), "Host disconnected, " + hostDesc,
        "If the agent for host [" + hostDesc + "] is not restarted within " + AlertWait + " seconds, host will go to Alert state");
```

`AlertWait` is the global setting `alert.wait`, 1,800 seconds by default: half an hour for someone to restart the agent ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L245-L246)):

```java
// cloudstack: engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java, lines 245–246
protected final ConfigKey<Integer> AlertWait = new ConfigKey<>("Advanced", Integer.class, "alert.wait", "1800",
        "Seconds to wait before alerting on a disconnected agent", true);
```

**A hang isn't cured by systemd.** The unit's `Restart=always` and `RestartSec=10s` ([A floor's machine](../../02.Architecture/01.Where-Everything-Lives.md#a-floors-machine)) restart the agent only when its program exits; a hung one stays hung until someone restarts it. Had it crashed, systemd would have started it again ten seconds later, and it would have dialled 8250 and introduced itself again.

**3. A zone with a pod, a cluster, a host and primary storage, but no secondary storage. What's missing under System VMs, and why can't anyone open a console?**

**The porter (SSVM) is missing.** It can't even be created without a warehouse ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/services/secondary-storage/controller/src/main/java/org/apache/cloudstack/secondarystorage/SecondaryStorageManagerImpl.java#L643-L649)):

```java
// cloudstack: services/secondary-storage/controller/src/main/java/org/apache/cloudstack/secondarystorage/SecondaryStorageManagerImpl.java, lines 643–649
protected Map<String, Object> createSecStorageVmInstance(long dataCenterId, SecondaryStorageVm.Role role) {
    DataStore secStore = _dataStoreMgr.getImageStoreWithFreeCapacity(dataCenterId);
    if (secStore == null) {
        String msg = String.format("No secondary storage available in zone %s, cannot create secondary storage VM.", dataCenterId);
        logger.warn(msg);
        throw new CloudRuntimeException(msg);
    }
```

It asks for an image store (the code's name for secondary storage) with free space in the zone. `null` means none, and the code gives up with that message.

**The window (CPVM) is missing too, which is less obvious.** The CPVM doesn't use the warehouse, but every system VM is made from the system VM template, and the template lives in the warehouse. The console proxy manager waits for it ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/consoleproxy/ConsoleProxyManagerImpl.java#L900-L907)):

```java
// cloudstack: server/src/main/java/com/cloud/consoleproxy/ConsoleProxyManagerImpl.java, lines 900–907
List<VMTemplateVO> templates = vmTemplateDao.findSystemVMReadyTemplates(dataCenter.getId(),
        HypervisorType.Any, null);
if (CollectionUtils.isEmpty(templates)) {
    if (logger.isDebugEnabled()) {
        logger.debug("System vm template is not ready at data center {}, wait until it is ready to launch console proxy vm", dataCenter);
    }
    return false;
}
```

No ready template in the zone, so `return false`: not yet. And with no CPVM, there's no console: the browser's console viewer connects to the CPVM's public address, and nothing else offers a VM's screen, to you or to a user of your cloud.

Your users can't do much either: templates, the room styles new VMs start from, live in the warehouse too.

**Once you add secondary storage**, the template is put in place: in 4.22, "During zone deployment and upgrade, the required templates … will be automatically registered and seeded on the secondary storage" ([System VM Template bundled with packages](https://docs.cloudstack.apache.org/en/4.22.1.1/adminguide/systemvm.html#system-vm-template-bundled-with-packages)). The code does it when the zone's first NFS secondary storage is added ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/storage/StorageManagerImpl.java#L4067-L4072)):

```java
// cloudstack: server/src/main/java/com/cloud/storage/StorageManagerImpl.java, lines 4067–4072

    if (zoneId == null || !DataStoreProvider.NFS_IMAGE.equals(providerName)) {
        logger.debug("Skipping system VM template registration as either zoneId is null or {} " +
                "provider is not NFS", store);
        return;
    }
```

The method is named for its job: register the system VM template on the zone's first NFS store. Anything that isn't NFS, or has no zone, is skipped. With a floor that's Up, primary storage and a ready template, both staff rooms can start, and the Quick Installation Guide's health check passes: "S-1-VM" and "V-2-VM" with Agent State Up.

**4. Which of these has its own line to the head office: a KVM host, a VMware host, the SSVM, the CPVM, the virtual router?**

| | Own line (port 8250)? | How the head office reaches it |
|---|---|---|
| KVM host | yes: the `cloudstack-agent` dials in | down the attendant's own line |
| SSVM | yes: it runs the same `AgentShell` | down its own line |
| CPVM | yes: it runs the same `AgentShell` | down its own line |
| VMware host | no | its "hands" sit in the head office and call vCenter on port 443 |
| Virtual router | no: its agent service is switched off | on KVM, through the host's attendant and SSH on port 3922 to its link-local address; on VMware, SSH on 3922 from the head office |

All three with a line have a row in the ledger's `host` table, the two staff rooms included (so do VMware hosts, whose hands make their check-ins inside the head office). The host types list the staff rooms, marked `true` as virtual ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/api/src/main/java/com/cloud/host/Host.java#L33-L37)):

```java
// cloudstack: api/src/main/java/com/cloud/host/Host.java, lines 33–37

    Storage(false), Routing(false), SecondaryStorage(false), SecondaryStorageCmdExecutor(false), ConsoleProxy(true), ExternalFirewall(false), ExternalLoadBalancer(
            false), ExternalVirtualSwitchSupervisor(false), PxeServer(false), BaremetalPxe(false), BaremetalDhcp(false), TrafficMonitor(false), NetScalerControlCenter(false),

    ExternalDhcp(false), SecondaryStorageVM(true), LocalSecondaryStorage(false), L2Networking(false);
```

`Routing` is CloudStack's historic name for a host that runs VMs; `ConsoleProxy` and `SecondaryStorageVM` are the window and the porter.

The staff rooms' line is also handled differently when it goes quiet. The head office doesn't investigate a silent SSVM or CPVM; it just disconnects it ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/engine/orchestration/src/main/java/com/cloud/agent/manager/AgentManagerImpl.java#L2014-L2022)):

**Why does the router get a management address on VMware?** On KVM, a router's control NIC gets a link-local address, reachable only from its own host. On VMware, the code gives it a management address instead, so the head office can reach it directly ([code](https://github.com/apache/cloudstack/blob/1a48a87587c03472feefb081cfac71b2ebd0f407/server/src/main/java/com/cloud/network/guru/ControlNetworkGuru.java#L142-L152)):
